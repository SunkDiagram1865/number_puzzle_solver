# 数字华容道求解器 v2.0

**新增图片识别** · 发布于 2026-10-24

---

## 概览

v2.0 在求解能力不变的前提下，补上了从 v1.0 起就一直挂在路线图上的短板：**不用再手工敲数字，直接把游戏截图丢进来就能解**。

新增的图片识别提供两条路径：

- **参考图匹配**（推荐）：盘面截图 + 参考原图 → NCC 相似度 + 匈牙利算法，实测准确率接近 100%
- **边缘拼接**：只有盘面截图 → 把 15 块当成一副被打乱的拼图重建，实测准确率 60% ~ 80%

同时按需求移除了 2×2 规格，并把图片上传的粘贴交互改成"悬停即选中"。

求解内核（IDA\* 最优解 / 逐层构造法）行为无变化，但**主程序整体重写**，代码结构与注释一并整理。

## 新增：图片识别

### 支持的输入方式

| 方式 | 说明 |
| :--- | :--- |
| 点击上传框 | 打开文件选择器 |
| 拖拽 | 把图片拖进对应上传框 |
| 剪贴板 | `Ctrl+V` 直接粘贴 |

两个上传位：**局面截图**（必填）与**参考原图**（可选）。粘贴目标由鼠标悬停决定。

### 处理流程

```
截图
 ├─ 边缘能量拟合等距网格（自动定位棋盘与格子边界，不要求截图正好裁齐）
 ├─ 切出 N² 格，按纹理方差定位空格
 ├─ 两条分支：
 │    有参考图 → 每块与目标格做 NCC，匈牙利算法求最优完美匹配
 │    无参考图 → 计算 4 个方向接缝代价矩阵 → 求解二次分配问题（QAP）
 ├─ 用「真实局面一定可解」这条先验筛选 / 修正结果
 └─ 回填到数字输入框，并给出网格检测图与还原图预览
```

### 无参考图时的搜索策略

QAP 是 NP-hard，采用多级启发式：

1. **贪心初值**：按行优先放置，每次选与左/上接缝代价最小的未用块
2. **模拟退火**：多起点，温度几何下降
3. **2-opt 局部搜索**：交换任意两块直到无改进
4. **迭代局部搜索**：随机扰动 2~4 次后再局部优化，重复数百轮
5. **3-cycle 加强**：对最优的若干候选做三循环，跳出仅靠交换无法逃离的局部最优
6. **奇偶性修正**：真实局面一定可解；若最优候选不可解，做一次"代价最小的交换"修正

### 实测准确率

以一张 4×4 游戏截图（1108×1111）与对应原图（550×571）为样本：

| 模式 | 准确率 | 耗时 |
| :--- | :---: | ---: |
| 参考图匹配 | **3 / 3** | ≈ 100 ms |
| 边缘拼接 | **4 / 5** | ≈ 300 ms |

识别结果：盘面 `6,3,5,2,1,0,7,4,13,8,14,12,10,11,9,15`，空格在 (2,2)，**最优解 28 步**。

> 两张输入图的尺寸、宽高比都不同，验证了"像素大小不同"这一场景。

## 变更

### 交互

- **粘贴目标改为悬停选中**：鼠标移到哪个上传框，就粘贴到哪个框，左上角显示「粘贴目标」徽标；**移出上传框或移出浏览器窗口即取消选中**。取消选中时粘贴回落到默认的「局面截图」。
- **修复"必须先点击才能粘贴"**：v1.0 → v2.0 开发中途曾把设置目标的动作写在 `click` 里，导致点击必然弹出文件选择器；现已改到 `mouseenter` / `focus`。
- **移除 2×2 规格**：阶数下拉现为 3×3 ~ 8×8。

### 代码

- **主程序整体重写**：求解器内核与界面逻辑重新组织，两份脚本各自职责清晰；文件从 ~1.4k 行增至 ~2.0k 行。
- **图片识别写成纯函数**：全部逻辑只依赖像素数组（`recognizeFromPixels(shot, n, ref)`），不碰 DOM，因此可以脱离浏览器在 Node 中直接测试。
- **新增辅助函数**：`rgcFitAxis`（网格拟合）、`rgcResample`（区域重采样）、`rgcGrayThumb` / `rgcNcc`（相似度）、`rgcHungarian`（匈牙利算法）、`rgcStrip` / `rgcEdgeCost`（接缝代价）、`rgcPlace`（摆放优化）、`rgcSolvable`（可解性）。

### 修复

- **接缝代价矩阵方向写反**：`costH[左][右]` 曾被写成 `costH[右][左]`，导致正确排列的代价是随机排列的 14 倍。修正后，正确邻居在代价矩阵中的平均排名从 **7.8 降至 1.14**。
- **块搬运回放索引取错**：状态编码为 `blank*T + tile`，回放时误取 `s % T`（块位置）而非 `(s/T)|0`（空格位置），导致搬运函数报告成功但块落在别处，构造法一度 **0/30** 全错。修正后恢复 **全绿**。

## 已知限制

1. **6 阶以上没有最优解** —— 受状态空间规模限制，属数学约束而非实现缺陷。
2. **个别极端 4×4 局面会超时** —— 例如理论最优 80 步的局面，程序会明确提示"未能确定最优解"，不会返回错误答案。
3. **5×5 难题可能耗时数十秒** —— 界面提供进度显示与「取消计算」。
4. **构造解不是最短解** —— 8×8 平均约 807 步，理论最优约 120 ~ 200 步。
5. **无参考图的图片识别准确率有限** —— 大面积纯色、渐变或纹理重复的画面（天空、水面、光斑）接缝信息不足，可能拼错几块。此时请提供参考原图，或对照「还原图」手工修正。程序会用可解性做兜底校验，并在可信度低时提示。
6. **图片识别假设目标局面右下角为空格** —— 与程序内置的目标盘面 `1,2,…,N²-1,0` 一致；若游戏的目标排列不同，需要手工调整。
7. **不保存历史记录** —— 刷新页面即清空。
