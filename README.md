# 数字华容道求解器 · Number Puzzle Solver

> 一个零依赖的单文件网页应用，用于求解 **3×3 ~ 8×8** 的数字华容道（N 数码 / Sliding Puzzle）。
> 3~5 阶返回**已证明的最少步数**，6~8 阶返回**可行解**并支持逐步演示。

## 简介

数字华容道（又称 N 数码问题、15-Puzzle）是一个经典的滑块谜题：在一个 N×N 的方格中放入 1 ~ N²−1 的数字，剩余一格留空；通过滑动数字块，将盘面还原为有序状态。

本项目是一个**纯前端、零依赖、单文件**的求解工具。它的目标不是"能玩"，而是**给出可验证的答案**：

- 在 3~5 阶上，返回的一定是**理论最少步数**——由可采纳（admissible）启发式下的 IDA\* 搜索保证，并已用 BFS 与独立 A\* 交叉验证；
- 在 6~8 阶上，如实告知"最优解在计算上不可行"，转而提供**构造法保证的可行解**，而不是给一个伪装成最优的近似值。

整个应用只有一个 HTML 文件，不加载任何外部资源，可在完全离线的环境下运行。

## 图片识别

除了手工填写，也可以直接把游戏截图丢进来。

### 两种模式

| | **参考图匹配**（推荐） | **边缘拼接** |
| :--- | :--- | :--- |
| 需要 | 盘面截图 + 参考原图 | 只要盘面截图 |
| 原理 | 归一化互相关（NCC）+ 匈牙利算法求最优匹配 | 把 15 块当成一副被打乱的拼图，靠接缝连续性重建 |
| 实测准确率 | ≈ 100% | ≈ 60% ~ 80% |
| 耗时 | ≈ 100 ms | ≈ 300 ms |

界面上传两张图即可自动走「参考图匹配」；只传一张则退化为「边缘拼接」。

### 处理流程

```
截图 ──► 边缘能量拟合等距网格（自动定位棋盘与格子边界）
     ──► 切出 N² 格，按纹理方差找空格
     ──► 两条路：
           有参考图 → 每块与目标格做 NCC，匈牙利算法求完美匹配
           无参考图 → 计算 4 个方向的接缝代价矩阵 → 求解二次分配问题(QAP)
     ──► 用「真实局面一定可解」这条先验筛选/修正结果
     ──► 回填到数字输入框
```

**无参考图时的搜索策略**（QAP 是 NP-hard，这里用启发式）：

1. 贪心初值：按行优先放置，每次选与左/上接缝代价最小的未用块；
2. 模拟退火：多起点，温度按几何下降；
3. 2-opt 局部搜索：交换任意两块直到无改进；
4. 迭代局部搜索：随机扰动 2~4 次后再局部优化，重复数百次；
5. 3-cycle 加强优化：对最优的若干候选做三循环（能跳出只靠交换到不了的局部最优）；
6. 奇偶性修正：真实局面一定可解，若最优候选不可解，则做一次「代价最小的交换」修正。

### 识别结果的可信度

界面会同时给出两张预览：**网格检测图**（蓝线为识别到的格线，橙色为空格）与**还原图**。还原图拼出来像一张完整的画，说明识别正确；如果画面错位，请提供参考原图或手工填写。

| | **最优解（最少步数）** | **快速解（保证可解）** |

## 算法设计

### 1. 最优解：IDA\*

采用 **IDA\***（Iterative Deepening A\*，迭代加深 A\*），配合曼哈顿距离与线性冲突双重启发式。

**启发函数**

```
h(n) = Σ manhattan(tile) + 2 × linear_conflicts
```

- **曼哈顿距离**：每个数字块当前位置到目标位置的横纵距离之和；
- **线性冲突**：同一行（或列）中，两个已位于各自目标行（列）却顺序颠倒的块，至少需要额外 2 步才能归位。

两者均**不高估**真实剩余代价，因此 IDA\* 首次找到的解即为最优解。

**迭代流程**

```
bound ← h(start)
loop
    t ← DFS(start, g = 0, bound)
    if 找到解      → 返回
    if t = ∞       → 无解
    bound ← t          // 取"超出阈值的部分"里最小的 f 值
```

**工程要点**

| 优化 | 说明 |
| :--- | :--- |
| 禁止回退 | 不将刚移动的块立即推回，减少大量无效分支 |
| 置换表 | 记录到达每个局面的最小 `g`，`g' ≥ g` 时剪枝 |
| **每轮清空置换表** | 上一轮是在更小阈值下剪枝的，保留旧条目会导致误剪（该缺陷曾令 60 个 3×3 样本中 59 个被误判为无解） |
| 容量上限 | 置换表超过 120 万条即清空，避免内存溢出 |
| 双上限 | 同时限制搜索节点数与耗时；超限时**如实报告失败**，绝不返回错误解 |

### 2. 规模上界分析

| 阶数 | 可达状态数（约） | 最优解可行性 |
| :---: | ---: | :--- |
| 3×3 | 1.8 × 10⁵ | 可穷举 |
| 4×4 | 1.0 × 10¹³ | 可求解（最难局面 80 步） |
| 5×5 | 1.0 × 10²⁵ | 难局面需数十秒 |
| 6×6 | 1.0 × 10⁴¹ | 不可行 |
| 7×7 | 1.0 × 10⁶² | 不可行 |
| 8×8 | 1.0 × 10⁸⁹ | 完全不可行 |

8×8 的状态数约 **10⁸⁹**，超过可观测宇宙的原子总数（约 10⁸⁰）。这意味着不存在能在可行时间内证明"某局面不可能更少步数"的算法。该结论是**数学上限**，而非实现或算力问题。

因此 6 阶以上转而追求"一定能解出来"，采用构造法。

### 3. 快速解：逐层构造法

核心思想是**逐层剥离**，每一步都只使用尚未归位的区域：

```
while 剩余棋盘 > 3×3:
    归位当前子棋盘的最上面一行
    归位当前子棋盘的最左边一列
    子棋盘左上各缩进一格
BFS 精确求解剩余的 3×3
```

已归位的格子被标记为 `frozen`，此后永不移动；末尾的 3×3 仅有 181 440 个可达状态，BFS 可在毫秒级完成。

实现中有两个关键难点，均通过**降低状态维度**解决：

#### 难点一：空格被推入死胡同

朴素做法是"给目标块规划路径，再把空格绕到它前面"，但当目标块被推入只进不出的角落时，空格会被困死，整盘僵住。

**解决方案**：以 `(空格位置, 目标块位置)` 为状态做 BFS，其余所有块视为**无差别的杂物**。状态数上限为 `n² × n²`（8×8 时为 4 096），一次 BFS 即可求出稳妥的推动序列，天然规避所有死锁。

#### 难点二：行／列的最后两格

一行的最后两格构成"角落 + 死角"结构：一旦其中一格被占用，另一格的入口便被彻底封死。**单独推动任何一个都必然失败**（实测中约半数局面会卡在此处）。

**解决方案**：以 `(A 的位置, B 的位置, 空格位置)` 为状态做三维 BFS，状态数上限 `(n²)³`（8×8 时约 26 万）。该算法能自动推导出类似人类高手的"先将两块摆成特定形状，再整体旋转入位"的策略。

> 三种转移（空格移动、推 A、推 B）在回放时均可统一为"将新状态中空格所在格滑入空格"，实现简洁且无歧义。

### 4. 运行架构

```
┌────────────────────────── 主线程 ──────────────────────────┐
│  界面逻辑 / 输入校验 / 可解性判断 / 动画演示                │
│                                                            │
│   new Worker(Blob(src)) ──成功──▶ Web Worker（后台计算）    │
│            │                                               │
│            └──失败──▶ new Function(src)（同源回退）         │
└────────────────────────────────────────────────────────────┘
```

求解器源码单独存放在 `<script type="text/js-worker" id="solver-src">` 中，主线程据此创建 Blob URL 的 Web Worker；若环境禁止 Worker，则用 `new Function()` 加载**同一份源码**在主线程执行。

**一份代码、两种运行方式**，不存在逻辑分叉。

## 已知限制

1. **6 阶以上无法给出最优解** —— 受状态空间规模限制，属数学约束而非实现缺陷。
2. **个别极端 4×4 局面会超时** —— 例如理论最优 80 步的局面，IDA\* 配合曼哈顿类启发式需数亿节点。程序会明确提示"未能在限制内确定最优解"，不会返回错误答案。
3. **5×5 难题可能耗时数十秒** —— 界面提供进度显示与「取消计算」按钮。
4. **构造解不是最短解** —— 8×8 平均约 799 步，理论最优约 120 ~ 200 步。可在构造后追加局部优化予以压缩。
5. **不保存历史记录** —— 刷新页面即清空，无本地存储。
6. **未针对触屏优化拖拽** —— 当前为填表式输入，而非直接拖动方块。
7. **无参考图的图片识别准确率有限** —— 大面积纯色、渐变或纹理重复的画面（天空、水面、光斑）接缝信息不足，可能拼错几块。此时请提供参考原图，或对照「还原图」手工修正。程序会用可解性做兜底校验，并在可信度低时提示。
